# CDMP pilot editorial review - 0.1.1

Review date: 2026-09-24. Baseline: draft PR #1 at `7391165df94a995be8903119bdb44910c90acd3f`.

## Decision

Keep the pilot in draft. All 40 stems, answer choices and answer keys received a second editorial pass. Twenty-five items changed, including source-only corrections; 15 were retained. No selected answer index changed. All option rationales for rewritten option sets were revised together.

This was a same-agent second pass with answer keys visible. It does **not** satisfy independent blind semantic review. Difficulty remains uncalibrated. The pilot still contains introductory recall and straightforward application items; it is not evidence of official exam difficulty or readiness.

## Material findings and resolution

- Several distractors were unrelated to the tested concept. Replaced them with adjacent concepts or credible implementation mistakes, without intentionally making multiple answers correct.
- Item 012 cited a nonexistent issue-management section. Corrected to Chapter 3, section 2.10, verified in the 2017 reference.
- Item 004 attributed the critical-data basis to the older architecture chapter. Corrected the 2017 locator to Chapter 13, section 1.3.2. The public revision notice confirms a definition was added to Chapter 4; its full wording has not been checked.
- Item 005 used the revised data-landscape term with a vague 2017 locator. Removed that locator; the public Chapter 4 revision notice is now the cited basis. The scenario interpretation still needs verification against the full Revised Edition.
- Item 020 did not fully distinguish registry from consolidation because both can preserve source ownership. Specified source retrieval without a central copy of master attributes.
- Item 021 omitted logical modeling and did not clearly bound the requested detail. Added logical modeling and explicit high-level scope.
- Item 022 omitted minimum participation. Specified mandatory order lines and tested both relationship ends.
- Item 023 could be confused with a legitimate historical address snapshot. Specified current contact data and a separate historical store.
- Item 035 needed more than successive dimension rows to guarantee correct attribution. Added sale-to-version linkage and a Type 3 distractor.
- The README called the items calibrated even though no response data exists. Removed that claim.

## Validation and remaining gates

- `npm run check`: repository audits, engine, jsdom application, CDMP and artifact-exclusion tests.
- Added mixed-answer scoring through the real app: 24/40 displays 60%, meets 60% and fails 70%/80%.
- Added edited-bank persistence coverage: an old fingerprint cannot resume, and old-version history remains stored but excluded from current comparisons.
- 5,000 pilot draws and 5,000 synthetic full forms check exact configured quotas. These are randomized simulations, not evidence of question difficulty or retake variety.
- Answer-length diagnostics after editing: correct option uniquely longest in 5/40, uniquely shortest in 12/40; mean correct length 53.3 characters, distractor length 54.6. These small-sample diagnostics cannot establish absence of answer cues.
- No browser rendering or visual accessibility sign-off was completed in this content pass. jsdom validates behavior, not layout.

Still required: independent reviewer answers with keys hidden and disagreement reconciliation; current Revised Edition verification; pilot response data for item difficulty, discrimination and distractor selection; broader bank coverage and retake-overlap checks; real-browser desktop/mobile and keyboard review. A passing runtime suite does not close these content gates.
